# 语音记忆输入 · 详细说明

## 解决的问题

普通语音输入每次都从零开始：同一句英语、同一个人名、同一个项目名，只要发音不标准，每次都会错成同一个样子。用户被迫每次手动改一遍。本插件把“改一遍”变成“教一次”：

1. 转写结果进入输入框；
2. 用户直接修改后发送；
3. 宿主读取真正发送的文本，与转写文本做对齐 diff；
4. 把改动固化为纠错记忆；
5. 下一次转写先应用记忆，再润色。

## 工作流

```
麦克风 / Alt
   ↓ MediaRecorder（浏览器）
16 kHz 单声道 float32 PCM
   ↓ POST /voice-memory  { action: "local-transcribe", sessionId }
SenseVoice（sherpa-onnx，本机 CPU）
   ↓ 原始文本
hot.txt 静态热词
   ↓
memory.json 学到的纠错（仅 source=asr）
   ↓
润色（默认开启，DSH 模型 + 风格记忆）
   ↓
写入输入框草稿
   ↓ 用户修改并发送
agent/pre-step → 对齐 diff → 更新 memory.json
```

## 记忆的两类内容

| 类型 | 何时产生 | 用途 |
| --- | --- | --- |
| `source: "asr"` 纠错 | 未开润色时对转写文本的修改；或开启润色但错误词仍在原文中 | 下一次转写时直接替换，修正发音/识别习惯 |
| `source: "style"` 表达偏好 | 开启润色时，对润色结果的进一步修改 | 追加到润色提示词，让改写更贴近用户表达 |
| `examples` 样例 | 每次相似度足够的修改 | 保留原始/最终对照，供风格提示与排查 |

单字纠错（如「在」→「再」）第一次只记录，出现两次后才参与自动替换；多字词、英文词第一次即可生效。

## 安全与隐私

- 音频只在本机转写，不上传云端（除非用户主动在设置中改用云端 ASR）。
- `memory.json` 只包含文本，不包含音频；位于 `$DSH_HOME/voice/`。
- `/voice-memory` 路由只接受 loopback / trusted host 的同源请求。
- 记忆写入失败不会阻断转写或发送。

## 设置面板

设置 → **语音记忆输入**：

- 识别引擎、语言、麦克风设备、热键、触发方式；
- 智能润色开关（默认开）、润色模型（自动选择第一个可用模型）、自定义润色提示词；
- 静态热词表 `hot.txt` 状态；
- **学习记忆**：条数、最近学到的纠错、逐条忘记、一键清空、记忆文件路径。

## 已知限制

- 只有发送才会触发学习；改了又清空不会学习。
- `@` 引用芯片会在整段写入时被展开为纯文本。
- 极长的整段重写不会被当作“发音习惯”，只保留为风格样例。
- 本地模型约 230MB；首次使用需要下载或复用已有模型。
